# 讲解标准与内容审查

## 材料盘点

输入可以只有聊天记录。没有课件时，从对话的问题、解释、例子、结论及未解决事项建立清单；来源标为任务／对话 ID、轮次、消息位置或导出文件位置，不编造章节页码。只有被引用且对理解必需、但实际未取得的材料才是读取缺口。非学习型讨论保留必要上下文、依据与决策理由，不机械添加自测或教材式例题。

课件目录用于定位，不是完整内容清单。阅读正文和关键原页后再登记：一个“系统调用”主题可能同时含 API 定义、传参图、完整 C 示例和练习，必须分别判断。保留原页码与文件名，不把页上的代码示意改称可运行实现。

建议使用 JSON 或 Markdown 表，字段包括 `item`、`type`、`source`、`learning_goal`、`required_evidence`、`main_location`、`status`、`judgment`。不要求特定序列化格式；关键是能追溯实质内容。

| 状态 | 判定标准 |
|---|---|
| 完整讲解 | 在约定学习层次上，必要证据都能在正文找到，读者可完成目标任务。判断理由指出具体解释、例子或代码位置。 |
| 只提及 | 只出现名称、结论、声明、概括表，或仍缺必要条件／步骤／例子；即便有锚点也不能判为完整。 |
| 材料不足 | 必要原文、图、上下文缺失，或存在无法解决的矛盾。区分“原材料不够”和“作者尚未补写”。 |
| 非学习内容省略 | 行政安排、联系方式、制作日志等不属于本次知识学习目标；写明省略原因，不放入附录。 |

写作前可将已取得但未解释的项目记为“只提及”。写作后人工复核状态；脚本可以找坏链接或空字段，不得按字段齐全、字数或术语命中率自动升级为“完整讲解”。课程范围完整、对话读取完整、单个知识点讲解充分是三个不同判断。

## 按类型定义“讲透”

### 概念
交代准确含义、必要前提和近邻概念的区别。需要时用例子检验边界。例如“进程”要能说明两个执行实例为什么要分别记录状态，而不仅是背“运行中的程序”。

### 机制
给定初始状态和参与对象，说明什么触发变化、谁执行关键步骤、状态怎样改变、何时完成，以及适用条件。可以用步骤、时序图或状态表，不要在图后逐句复述。

### 公式
解释符号与单位、假设、关系从何而来、关键中间步骤、使用条件；至少用一个适量的具体情境展示如何使用。不要只有排得漂亮的公式，也不要为每个简单关系硬加长推导。

### 代码与例题
保留与学习目标相关的教学逻辑：必要的声明／输入准备、分支或循环、数据处理与结果。自足片段允许省略明确无关的外围代码，但必须说明上下文；函数声明不能代替实现示例，表格只能辅助比较。

顺序可采用：**原例及其意图 → 关键语句 → 具体输入的执行轨迹 → 缺陷与边界 → 修正版 → 变式**。不要求每次都显示这些标题，但内容必须够用。

- **原例**：保留关键执行逻辑。修正弯引号、断行等排版字符时说明；删除注释可以，但不得把实质修改悄悄算作原文。
- **轨迹**：从具体输入写到可观察输出；同时追踪变量、有效长度、缓冲区和终止状态。声明“预期结果”和“实测结果”时用词准确。
- **修正版**：逐项对应原例问题。改变缓冲区大小、输入协议、错误处理或输出格式时说明。不要为一个教学示例扩建完整业务系统。
- **运行验证**：先检查环境。POSIX 代码在适配的 Linux／WSL 验证；不能以 Windows 上的文本检查代替运行。记录编译器、命令、输入、stdout、退出码和测试边界。正常输入、空输入和直接影响目标的边界足够起步，发现问题再扩展。
- **无法运行**：标为未运行或伪代码，保留静态推演与限制，不捏造验证。原例存在未定义行为时可静态解释，没必要为了复现而运行不可靠程序。

### 图示
明确对象、方向、关系和条件。组成、时间顺序、先修依赖与因果不是同一种边。图中的多个对象同时变化时应追踪各自状态；不要只留下图名或把图转成没有关系的术语列表。

## 结构与复习

全局地图先给主要问题与模块关系，每个节点链接主要讲解位置；局部图用于难点。分组与深度随材料变化，不固定六模块，不固定每模块相同长度。对复杂设计说明约束与取舍，不宣称唯一设计由第一性原理必然推出。

每个重要概念保留一个主要解释位置。复现同一概念只用于不同任务：地图定位、例子执行、自测重建、综合题迁移。正文／表格／提示框中没有信息增量的重复删除；必要前提、步骤、例子不得因“显得长”而删除。

自测与例子有条件变化，而非仅将例题数字原样问一遍。逐题写出答案依赖的正文位置；若需要未教过的结论，补正文或修改题目。核心讲解常显，只有答案默认收起。说明新增题目来自整理，不把模型设问当成用户的个人疑惑。

## 四项审查记录

来源／事实、内容、教学、渲染分别记录结果与证据。尤其防止：可打开 HTML → 内容好；存在代码块 → 例题讲透；代码编译 → 所有行为正确；PDF 文字相同 → 原文正确；两次生成 → 稳定保证。这些推断都不成立。

重复验证从同一材料另写代表性模块，不复制首稿改标题。允许复用同一份已验证代码与模板，但两份正文独立组织；比较知识目标、关键步骤、例子、边界及答案依据，说明哪些内容是共享的、是否同一作者。结果可能是两稿均通过，也可能有缺口，按实际记录。

## 方法依据

[IES 实践指南](https://ies.ed.gov/ncee/WWC/PracticeGuide/1)建议结合图文、抽象与具体表征、例题与练习，并使用检索和间隔复习。[Karpicke 与 Blunt（2011）](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf)的科学文本实验支持在概念图学习之外安排主动回忆。这些依据支持本设计的选择，不证明某种笔记外观对所有学科都最优。
