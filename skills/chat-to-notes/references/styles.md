# 六种风格：生成前选择，整份文档固定

向用户展示下表名称与特点，使用稳定 ID 保存选择。用名称回答优先；用户按编号选择时，以本次展示的列表为准，存在歧义再澄清。用本表选择，不必每次重做样图。

| 选项 | ID | 特点 |
|---|---|---|
| 康奈尔线索笔记 | cornell | 左侧回忆问题，右侧充分讲解，模块末简短收束；适合读后回忆。 |
| 层级大纲笔记 | outline | 按前提、概念与推理依赖分层；适合系统通读，不将正文压成关键词。 |
| 例题与旁批 | annotated | 完整例题旁标关键步骤理由、易错条件；适合跟踪解题或代码执行。 |
| 图解手写笔记 | sketch | 方格纸、克制强调、图文邻近；以图表达有必要可视化的关系。 |
| 经典手写风 | handwritten | 保留原有楷体、浅色纸张、通栏讲解。 |
| 规范风 | electronic | 保留原有规范字体、清晰层级与简洁通栏。 |

建议问法：“这份笔记想采用哪一种？康奈尔线索／层级大纲／例题旁批／图解手写／经典手写／规范风。选定后 HTML 和 PDF 将保持这一风格。”这是生成偏好选择，不是权限审批。有明确风格的请求不再问。

## 正文结构约定

标题与地图继续使用基础模板的 h2/h3 稳定 id。按知识点分块，不把整章套进一张大表，不把样图的一页长度当作篇幅上限。核心知识常显；答案开合与风格无关。

**cornell**：每个有意义的知识块用 `.note-unit`，其中 `.cue` 是遮盖正文后可回答的短问题，`.note-main` 是完整正文，可选 `.note-summary` 只收束新关系。主栏放公式、图、代码；左栏不能重复整段答案。

```html
<div class="note-unit"><aside class="cue">为什么这一步能推出全局结论？</aside>
<div class="note-main"><h3 id="global-condition">全局条件</h3><p>充分讲解与必要例子……</p></div></div>
```

**outline**：h2 为模块，h3 为知识点，相关解释用 `.outline-unit` 分组。按需增加一层列表；推导、代码与例题保留段落和完整步骤，不能只留缩进标题。

**annotated**：真实例题或过程使用 `.annotated-example`，其中 `.example-steps` 放完整执行过程，`.margin-note` 用步骤号关联关键依据。多个复杂步骤可拆成多个这样的块；一般概念仍正常通栏，不为两栏强行造题。

```html
<div class="annotated-example"><div class="example-steps"><p>① 输入、步骤与结果……</p></div>
<aside class="margin-note"><p>① 这里使用的条件与原因……</p></aside></div>
```

**sketch**：相关解释和图放进 `.visual-explanation`；图有对象、关系、标签和文字说明。科学曲线由已核对公式计算，原课件图先核对再裁取或重绘。图是理解证据，不是生成式绘图模型臆造的公式截图。纯概念没有合适图时，使用关系清楚的步骤或对照，不硬造曲线。

**handwritten / electronic**：延续基础模板的 `.worked-example`、`.formula`、`.retrieval` 等组件，无需增加双栏。

## 跨媒介约束

窄屏允许双栏按原阅读顺序上下排列；A4 打印恢复可读栏宽。字体、配色、强调方式及内容关系不因导出换成别的风格。长推导先按等式逻辑断行；仍过宽的图或公式可独占通栏并拆分双栏块，不能裁掉右半部分或缩到不可读。

各风格共用内容充分性标准。视觉模板不证明逻辑正确；人工审查条件、符号、推导和变式依赖后，才将对应知识项标为完整讲解。
